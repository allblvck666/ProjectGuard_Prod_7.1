# Новый слой представления (редизайн)

Слой живёт рядом со старым: старые экраны не удалены и работают как раньше.
Новый экран включается флагом — по умолчанию везде старый.

## Флаги

| Флаг         | Что включает                          | Этап |
|--------------|---------------------------------------|------|
| `ui-list`    | список активных защит                 | 2    |
| `ui-detail`  | карточка защиты (из списка и архива)  | 3    |
| `ui-create`  | создание + экран конфликта            | 4    |
| `ui-nav`     | нативные BackButton / MainButton      | 5    |
| `ui-archive` | архив защит                           | 6    |
| `ui-admin`   | админка и статистика                  | 6    |
| `ui-kit`     | витрина дизайн-системы (`on` / `off`) | 1    |

Значения: `new` / `old` (для `ui-kit` — `on` / `off`).

Переключение:

```
?ui-list=new        включить новый список
?ui-list=old        вернуть старый
?ui=new             включить все новые экраны сразу
?ui-kit=1           открыть витрину дизайн-системы
```

Выбранное значение запоминается в `localStorage` (`pg_ui_flags`), поэтому переживает
перезапуск Mini App. Из консоли:

```js
window.__pgFlags()                     // текущее состояние
window.__pgFlags().set('ui-list','new')
window.__pgFlags().reset()             // вернуть всё к старому UI
```

## Файлы

- `tokens.css` — токены, обе темы, базовые компоненты (`pg-*`)
- `theme.js` — выбор темы из Telegram themeParams / colorScheme → `data-pg-theme` на `<html>`
- `flags.js` / `useFlags.js` — флаги и подписка на них
- `icons.jsx` — единый SVG-набор, `<Icon name="..." />` (эмодзи в новом слое не используются)
- `ui.jsx` — кнопка, карточка, бейдж, поле, сегмент, боттом-шит, состояния
- `format.js` — форматирование данных защиты (артикулы, метраж, срок, статус)
- `telegram.js` — нативные BackButton / MainButton, хаптика, свайпы
- `ProtectionsList.jsx` + `list.css` — список активных защит
- `ProtectionDetail.jsx` + `detail.css` — карточка защиты (слой поверх списка/архива)
- `ActionSheets.jsx` — подтверждения действий, общие для списка и карточки
- `CreateProtection.jsx` + `create.css` — создание защиты
- `ConflictScreen.jsx` — экран конфликта (дубликат: тот же артикул и метраж ±10%)
- `SkuPicker.jsx` + `form.css` — выбор артикулов
- `ArchiveList.jsx` — архив защит
- `StatsScreen.jsx` + `stats.css` — статистика
- `AdminScreen.jsx` + `admin.css` + `admin/` — админка (5 вкладок)
- `UiKit.jsx` — витрина дизайн-системы (`?ui-kit=1`)

## Правила

- Бизнес-логика, `api.js` и контракты не меняются — только представление.
- Новые классы всегда с префиксом `pg-` (дизайн-система) или `pgl-` (экраны),
  чтобы не пересекаться со старым `styles.css`.
- Навигацию (шапка, «Назад», нижняя кнопка) рисует Telegram — своя не верстается.
  При `ui-nav=new` App вешает на `<html>` атрибут `data-pg-nav="native"`, по нему
  прячутся «← Назад» (класс `pg-legacy-back`) и плавающая стрелка `.fixed-back-button`
  на старых экранах. Атрибут ставится только внутри Telegram: в браузере
  BackButton/MainButton не рисуются, и без запасных кнопок экран стал бы тупиком.
- «Назад» может понадобиться нескольким слоям сразу (список → карточка), поэтому
  `useBackButton` — реестр с приоритетами `BACK_PRIORITY` (app / screen / overlay / sheet),
  а не порядок монтирования: React выполняет эффекты детей раньше родителей.
- Общие элементы (поиск `pg-search`, чипы `pg-chip`, кнопки, карточки) живут в
  `tokens.css`, а не в CSS отдельного экрана: экраны грузятся лениво, и стиль
  из чужого файла может просто не приехать.
- В новом слое не используются голые `<p>`: на экранах ≤480px `styles.css`
  задаёт им `font-size: 1rem !important`. Текстовые блоки — `div` со своим классом.
