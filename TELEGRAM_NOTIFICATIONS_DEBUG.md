# 🔍 Отладка Telegram-уведомлений

## Проблема
Уведомления не приходят в Telegram при запросе на продление защиты.

## Возможные причины

### 1. Проблема с BackgroundTasks
**Симптом:** `RuntimeWarning: coroutine 'send_admin_notifications' was never awaited`

**Решение:** Используется `BackgroundTasks` из FastAPI, который автоматически инжектится в endpoint.

### 2. Проблема с форматом tg_id
**Симптом:** Уведомления не отправляются из-за неправильного формата `tg_id`

**Проверка:**
- В базе данных `users.tg_id` может быть в формате:
  - Числовой ID: `123456789`
  - С префиксом: `tg-79207455960` или `dev-79207455960`
- Код автоматически убирает префиксы и конвертирует в `int`

### 3. Проблема с инициализацией бота
**Проверка:**
- `BOT_TOKEN` должен быть установлен в переменных окружения
- Бот должен быть инициализирован: `bot = Bot(token=BOT_TOKEN)`
- Бот должен быть запущен через `start_tg_bot()`

### 4. Проблема с правами бота
**Проверка:**
- Бот должен иметь возможность отправлять сообщения пользователям
- Пользователь должен начать диалог с ботом (отправить `/start`)

## Логи для отладки

При запросе на продление в логах должны появиться:
```
🔍 Начинаю отправку уведомлений админам. Всего админов: X
🔍 BOT_TOKEN exists: True, bot instance: True
📤 Отправляю уведомление админу {tg_id_int}...
✅ Уведомление о запросе продления отправлено админу {tg_id_int} ({admin_name}), message_id={message_id}
```

Если уведомления не отправляются, проверьте:
1. Есть ли админы в базе данных с `tg_id`
2. Правильный ли формат `tg_id` (числовой или с префиксом)
3. Инициализирован ли бот
4. Установлен ли `BOT_TOKEN`

## Как проверить tg_id админа

В админке в разделе "Пользователи" проверьте поле `tg_id` у админов/суперадминов.

Если `tg_id` в формате `tg-79207455960`, код автоматически извлечет `79207455960` и отправит уведомление.

## Как проверить, что бот работает

1. Отправьте боту `/start` в Telegram
2. Бот должен ответить с кнопкой "Войти в систему"
3. Если бот не отвечает - проверьте `BOT_TOKEN`
