## 🎯 Задача 1: Ограничение количества SKU до 3

### Проблема
После выбора третьего артикула интерфейс всё равно добавлял 4-е пустое поле.

### Решение

**Файл:** `frontend/src/App.jsx`

**Изменения в компоненте `SkuSelector`:**
1. Добавлена константа `maxSkus = 3`
2. Добавлена проверка `canAddMore = selected.length < maxSkus`
3. Поле ввода и подсказки скрываются, когда уже выбрано 3 артикула
4. Добавлено информационное сообщение: "⚠️ Максимум 3 артикула. Удалите один, чтобы добавить другой."

**Код:**
```javascript
const maxSkus = 3;
const canAddMore = selected.length < maxSkus;

// Поле ввода показывается только если можно добавить еще
{canAddMore && (
  <>
    <input className="input" placeholder="Введите артикул..." ... />
    {suggestions.length > 0 && <div className="suggestions">...</div>}
  </>
)}
```

**Результат:**
- ✅ Максимум 3 артикула в форме
- ✅ После выбора 3-го артикула поле ввода скрывается
- ✅ Пользователь видит предупреждение, если пытается добавить 4-й
- ✅ Существующая валидация не нарушена

## 🎯 Задача 4: Авто-закрытие защит "за бездействие"

**Файл:** `backend/main.py`

**Функция:** `auto_close_expired_protections()`

**Изменения:**

1. **Добавлено поле `close_reason` в таблицу `protections`:**
   - Миграция в `backend/db.py`
   - Миграция в `backend/main.py` (`_safe_migrate()`)

2. **Логика авто-закрытия:**
   - Проверяет все активные защиты, срок которых истёк (`expires_at < now`)
   - Закрывает только те, у которых `auto_closed = 0` или `NULL`
   - Устанавливает:
     - `status = 'closed'`
     - `auto_closed = 1`
     - `close_reason = 'закрыта за бездействие'`
     - `closed_at = now`
   - Записывает в историю с `action='close'` и `reason='закрыта за бездействие'`

3. **Уведомления:**
   - **Менеджеру:** отправляется уведомление об авто-закрытии с полными данными
   - **Админам/суперадминам:** отправляется уведомление о факте авто-закрытия

4. **Периодичность:** проверка каждые 6 часов

**Код:**

                       u.tg_id
                FROM protections p
                LEFT JOIN users u ON u.id = p.manager_id

## 🎯 Задача 5: Улучшение отображения в архиве

**Файл:** `frontend/src/App.jsx`

**Компонент:** `ArchivePage`

**Изменения:**

1. **Статус для авто-закрытых защит:**
   - Если `close_reason` содержит "бездействие", статус отображается как "⏰ Закрыта (автоматически)"

2. **Визуальное выделение:**
   - Авто-закрытые защиты имеют жёлтый фон вместо красного
   - Иконка ⏰ вместо 🔒

**Код:**
```javascript
const statusText = 
  it.status === "success" ? "✅ Успешна" :
  it.status === "closed" && it.close_reason && it.close_reason.includes("бездействие") 
    ? "⏰ Закрыта (автоматически)" 
    : it.status === "closed" ? "🔒 Закрыта" :
  it.status === "deleted" ? "🗑️ Удалена" : it.status;

// В карточке защиты
{it.close_reason && (
  <div className="small" style={{ 
    background: it.close_reason.includes("бездействие") 
      ? "rgba(255, 193, 7, 0.1)"  // Жёлтый для авто-закрытия
      : "rgba(239, 68, 68, 0.1)",  // Красный для обычного закрытия
    ...
  }}>
    {it.close_reason.includes("бездействие") ? "⏰" : "🔒"} 
    <b>Причина закрытия:</b> {it.close_reason}
  </div>
)}
```

**Результат:**
- ✅ Авто-закрытые защиты визуально отличаются
- ✅ Причина закрытия отображается в карточке

## 🔧 Технические детали

### База данных (миграции):

- `reminder_2days_sent INTEGER DEFAULT 0` - флаг отправки напоминания за 2 дня

**Миграции:**
- Автоматически выполняются при старте приложения через `_safe_migrate()`

### Telegram-бот:

**Используется единый экземпляр бота:**
- `bot = Bot(token=BOT_TOKEN)` (глобальный)
- Все уведомления отправляются через этот экземпляр
- Асинхронная отправка через `asyncio.create_task()`

**Получатели уведомлений:**
- Админы/суперадмины: все пользователи с `role IN ('admin', 'superadmin')` и `tg_id IS NOT NULL`
- Менеджеры: пользователь-менеджер + все привязанные через `manager_id` или `manager_ids`
